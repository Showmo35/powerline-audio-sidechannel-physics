# Module 4 UNet - Soundbar

This folder implements a standalone UNet reconstruction pipeline for the new Soundbar dataset.

## Audio chunk creation

Clean targets are generated by:

`<REPO_ROOT>/Powerline_Data_Captures/build_audio_chunks.py`

How it works:

- Recursively reads LibriSpeech `.flac` files in sorted order.
- Concatenates them into fixed 30-minute chunks (default) at 16 kHz.
- Writes files as `chunk_001.wav`, `chunk_002.wav`, ... in `audio_chunks/`.
- Supports resume via `build_progress.json` if interrupted.

## How `.bin` and `.wav` are aligned

In this module (`prepare_data.py`):

- Soundbar leakage comes from `Soundbar/LibriSpeech/chunk_XXX.bin`.
- Clean audio comes from `audio_chunks/chunk_YYY.wav`.
- Default mode is `sequential` pairing: it pairs all available soundbar chunks with the last `N` audio chunks, where `N = min(#bin, #wav)`.
- Optional mode `direct` pairs same index (`chunk_012.bin -> chunk_012.wav`) when indices match.
- For each pair, preprocessing uses the last 30 minutes (`tail_sec=1800` by default), then creates train/val windows (90/10 split).

## Pipeline

Raw `chunk_*.bin` leakage is paired with the corresponding `chunk_*.wav` audio target. The last 30 minutes of each pair are used, and the prep step reads the raw leakage tail with `np.memmap` so the full bin file never needs to be loaded into RAM.

The data pipeline is:

`bin tail -> bandpass -> resample to 16 kHz -> 80-bin log-mel windows -> sharded npz -> UNet -> reconstruction`

## Why this module exists

- It keeps the original UNet training path, without Whisper perceptual loss.
- It avoids OOM during data prep by processing the tail in smaller segments and writing compact shards to disk.
- It works with the new Soundbar captures under `Powerline_Data_Captures/Soundbar/LibriSpeech` and `Powerline_Data_Captures/audio_chunks`.

## Files

- `prepare_data.py` builds sharded training/validation windows from aligned chunk pairs.
- `dataset.py` loads sharded or legacy dense `.npz` files.
- `model.py` contains the UNet and L1 + multi-scale STFT loss.
- `train.py` trains the UNet on the prepared shards.
- `inference.py` evaluates the model on the validation split.
- `run_all.sh` runs prep, train, and inference on SLURM.

## Usage

```bash
cd "<REPO_ROOT>/Module4_UNet_Soundbar"
python prepare_data.py
python train.py
python inference.py
```

For SLURM, use:

```bash
sbatch run_all.sh
```

## Notes

- The default pairing mode is sequential and end-anchored, which matches the observed capture layout for the Soundbar data.
- If your capture numbering changes, `prepare_data.py` also supports a direct same-index pairing mode.
- If storage becomes tight, reduce `--segment_sec` or set `--max_windows_per_pair` to cap the number of extracted windows per pair.
